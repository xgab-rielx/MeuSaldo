# MeuSaldo

MeuSaldo é um aplicativo web responsivo para controle de gastos pessoais. O backend usa FastAPI e PostgreSQL hospedado no Supabase. Cada conta acessa somente os próprios gastos.

O aplicativo permite cadastrar, listar, editar e excluir gastos, filtrar por período e categoria e consultar o total gasto no mês.

## Funcionalidades

- Cadastro de gastos com descrição, valor, data e categoria
- Listagem, consulta, edição e exclusão de gastos
- Filtros por período e categoria
- Consulta do total mensal
- Login e logout com sessão
- Isolamento dos gastos por usuário
- Interface web responsiva

## Tecnologias

- Python e FastAPI
- PostgreSQL no Supabase
- Psycopg para conexão com PostgreSQL
- Pydantic
- `pwdlib` com Argon2 para armazenar hashes de senha
- Starlette `SessionMiddleware` para sessões
- `python-dotenv` para carregar configurações locais do `.env`
- HTML, CSS e JavaScript

## Banco de dados

O aplicativo usa PostgreSQL no Supabase. Para configurar um projeto Supabase novo, crie as tabelas abaixo pelo **SQL Editor**. Se as tabelas já existem, pule este passo.

```sql
CREATE TABLE users (
    user_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL
);

ALTER TABLE users ENABLE ROW LEVEL SECURITY;

CREATE TABLE spendings (
    spending_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(user_id),
    description TEXT NOT NULL,
    category TEXT NOT NULL,
    value TEXT NOT NULL,
    date TEXT NOT NULL
);

ALTER TABLE spendings ENABLE ROW LEVEL SECURITY;
```

Para a aplicação, use a URL **Transaction pooler** do Supabase, na porta `6543`. Consulte [o guia de conexão do Supabase](https://supabase.com/docs/guides/database/connecting-to-postgres) e copie os dados de conexão do painel; não compartilhe a URL, pois ela contém credenciais.

## Como executar localmente

1. Clone o repositório:

```bash
git clone https://github.com/xgab-rielx/MeuSaldo.git
cd MeuSaldo
```

2. Crie e ative um ambiente virtual:

```bash
python -m venv .venv
```

No Windows:

```powershell
.venv\Scripts\activate
```

No Linux ou macOS:

```bash
source .venv/bin/activate
```

3. Instale as dependências:

```bash
pip install -r requirements.txt
```

4. Crie um arquivo `.env` na raiz do projeto com estas variáveis:

```dotenv
DATABASE_URL=cole_a_url_do_transaction_pooler
SESSION_SECRET=cole_uma_chave_aleatoria
SESSION_COOKIE_SECURE=false
```

Gere uma chave aleatória para `SESSION_SECRET` com:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Cole o resultado no `.env`. Substitua também o valor de exemplo de `DATABASE_URL` pela URL copiada do Supabase. Se a senha do banco tiver caracteres reservados, como `@`, `#` ou `&`, codifique-os na URL. O arquivo `.env` está listado no `.gitignore` e não deve ser enviado ao Git.

5. Inicie o servidor:

```bash
uvicorn main:app --reload
```

6. Acesse a interface e a documentação:

- Interface: <http://127.0.0.1:8000/app>
- Documentação interativa: <http://127.0.0.1:8000/docs>

`SESSION_COOKIE_SECURE=false` permite testar o login localmente por HTTP. Na Vercel, configure essa variável como `true` e cadastre `DATABASE_URL` e `SESSION_SECRET` nas configurações do projeto. Não use o arquivo `.env` no deploy.

## Criar uma conta

Não há cadastro público. Para criar uma conta, abra um terminal na raiz do projeto, com o ambiente virtual ativado, e inicie o Python:

```bash
python
```

No console interativo, execute:

```python
from dotenv import load_dotenv
load_dotenv()

from getpass import getpass
from database import create_user
from security import hash_password

username = input("Usuário: ")
password = getpass("Senha: ")
user_id = create_user(username, hash_password(password))
print(f"Conta criada com ID {user_id}")
```

`getpass` não exibe a senha enquanto você digita. O banco guarda o hash da senha, não a senha original. Para sair do console, digite `exit()`.

## Endpoints

| Método | Rota | Descrição |
|---|---|---|
| `POST` | `/login` | Inicia uma sessão com usuário e senha |
| `POST` | `/logout` | Encerra a sessão atual |
| `GET` | `/session` | Verifica se há uma sessão ativa |
| `POST` | `/spendings` | Cadastra um gasto da conta conectada |
| `GET` | `/spendings` | Lista os gastos da conta, com filtros opcionais |
| `GET` | `/spendings/monthly_total` | Retorna o total mensal da conta conectada |
| `GET` | `/spendings/{spending_id}` | Busca um gasto da conta pelo ID |
| `PUT` | `/spendings/{spending_id}` | Atualiza um gasto da conta |
| `DELETE` | `/spendings/{spending_id}` | Remove um gasto da conta |

As rotas de gastos exigem login. O `user_id` é obtido da sessão, não de um valor enviado pelo navegador.

## Filtros na listagem

A rota `GET /spendings` exige uma sessão ativa e aceita estes parâmetros opcionais:

- `start_date`: data inicial, no formato `YYYY-MM-DD`
- `end_date`: data final, no formato `YYYY-MM-DD`
- `category`: categoria exata do gasto

Exemplo:

```text
GET /spendings?start_date=2026-11-01&end_date=2026-11-30&category=alimentacao
```

## Total mensal

Exemplo:

```text
GET /spendings/monthly_total?year=2026&month=11
```

O total considera apenas os gastos da conta conectada.
